# Docker Cleanup 0.4.0

First public release: a Linux desktop Docker storage explorer with explicit,
reviewed cleanup workflows. Licensed under MIT.

## Highlights

- Project/category treemaps, searchable asset tables, clear storage boundaries
  and full-name hover/focus disclosure.
- Explainable Compose/devcontainer attribution, friendly names, project
  overrides and persistent protection.
- On-demand filesystem change paths, metadata with environment omitted and
  container process evidence, without starting stopped containers.
- Explicit cleanup review, separate volume/cache acknowledgements, per-action
  progress, cancellation and saved local result history.
- Local Unix sockets plus explicitly selected SSH/verified mutual-TLS Docker
  contexts. Remote support uses existing Docker/OpenSSH authentication.
- Light/Dark/System themes and resizable, keyboard-accessible panes.

## Install

Download `docker-cleanup_0.4.0_amd64.deb` and
`docker-cleanup_0.4.0_amd64.deb.sha256` from this release. In the download directory:

```bash
sha256sum -c docker-cleanup_0.4.0_amd64.deb.sha256
sudo apt install ./docker-cleanup_0.4.0_amd64.deb
docker-cleanup
```

Run as a normal desktop user, not root. Debian 12/Linux amd64 is the native
build/test baseline. Existing local development installations retain the
application ID, SQLite data, history and preferences; close the app before
upgrading. Docker CLI is optional for local Unix sockets and required for
remote contexts.

## Safety and limitations

Deletion is irreversible; there is no backup or undo. Container deletion retains
unselected volumes and bind mounts, and volume deletion requires an additional
data-loss acknowledgement. Running/protected assets and changed references
cannot bypass review. Storage/recovery estimates are logical data, not a promise
of physical disk recovery.

SSH/TLS transport is exercised with real authenticated connections against
synthetic Engine APIs. This does not prove behavior against an external
production host, arbitrary SSH/CLI versions, hardware keys, proxies or actual
rootless Engines. Windows/macOS/ARM packages, insecure TCP/TLS, external buildx,
portable per-directory writable-layer sizing and automatic cleanup are not
supported.

The CI run linked to this release contains test reports and the same-environment
two-build Debian comparison. `release-manifest.json` records the source commit,
workflow run and package SHA-256. Checksums detect corruption; the manifest is
not a cryptographic signature or an independent reproducibility attestation.
